Do you sometimes wish you could just declare things that can not be declared as default?
This is actually possible with declarative plugins / modules.

Let's say for example that you have nix installed on this Haliade system
Nix, being a seperate package manager, it's packages can not be declared until you use a helper module.

A helper allows you to add modules to your declarative configuration,
To add a declarative module, you must install a generator at /usr/lib/declaration/generators
They are installed automatically if you install a helper package, but if it is not packaged, you may need to manually add the generator

After the generator is added, you need to edit /etc/haliade/enabled_modules.lua to enable the module generator, this is necessary for your config to act on the section the plugin adds.
Inside the file are all the modules or generators that are enabled for the declarative configuration, remove one from the list, and it'll be disabled, add one, and it'll be enabled if it is a generator.
The list lives in /etc (not inside the declaration package), so neither a declaration update nor installing the helper can ever reset it — only you change what is enabled.

Your declaration in /etc/haliade/definition.lua already accepts any section you write in it; an enabled generator is what makes that section do something.
A helper package can also ship a plugin config to /etc/haliade/plugin-configs, which your declaration reads automatically on every sync.
Plugin configs give an added section a default value and type checking, the same as the built-in sections have, so a mistyped section is reported instead of silently ignored.
For example the nixpkgs helper ships /etc/haliade/plugin-configs/nixpkgs.lua, which is why the ["nixpkgs"] section works out of the box once the generator is enabled.

After setting up the helper module / plugin, you will be able to declare what you want to declare!
